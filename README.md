## 先读这段

这套文件用于把一个项目交给多名 agent 协作，不是让每名 agent 各做一款游戏。

- 用户已经确认：养成/农场方向、多人共享世界、玩家 A 当服务器、世界内贡献和收益榜、未来团体自建服务器、渐进迭代与清晰解耦。
- 《微风小镇》第一版以镇上的公共农场为游玩区域；名称不增加 NPC 日程、自由建城或多地图等首版范围。
- 地图大小、人数上限、共享资金、作物数量、平台和技术栈等是本任务包提出的默认方案，不冒充用户已经确认的决定。
- 2026-09-08 用户已授权开始执行；当前启动 M0 工程与流程任务，真实状态见 [执行任务板](docs/execution/task-board.md)。
- 先完成 M0 风险验证与契约冻结，再开展多人并行实现。不要把“预留扩展点”变成提前开发未来所有功能。
- “第一版成品”不等于《星露谷物语》的内容规模，也不等于已经满足商店上架条件。

## 第一版的一句话定义

一款原创 2D 俯视角合作农场游戏：1 人可玩、2–4 人联机；房主保存世界，大家种植、浇水、收获、出售、完成公共建设；游戏内显示累计收益、当日收益和贡献榜，并可经授权导出公开榜单快照。

第一版要验证的产品目标：朋友能进入同一个农场，完成一次分工种植和共同建设，看懂个人贡献与团队资金，并在退出后继续同一份进展。交付终点是通过验收的 0.1.0 封闭测试包、操作手册和测试证据；M0 技术实验、M1 单人切片都是中间成果。

## 第一轮分派建议

1. 主执行者承担 LEAD，已记录角色分配；先推进 M0 风险实验与契约冻结。
2. 按 `05-execution-readiness.md` 的已填任务卡先执行 `FND-01`，可同时执行 `UI-01`。引擎基线完成后，再分派 `FND-02`、`NET-01`、`DATA-00`、`QA-01`；根据可用人数分批，实验使用独立目录。
3. LEAD 汇总上述证据完成 `LEAD-01`，冻结版本、接口、存档模型与写入范围后，再分派正式领域与存储实现。
4. 后续最多同时推进 3–5 个独立实现任务。缺少依赖的 agent 先使用契约样例，不自行创造另一套协议。
5. 将任务文件中的分派模板复制给对应 agent；不要只发一句“按 PRD 开始开发”。

## 必须守住的红线

- 房主玩家与远端玩家经过同一业务校验，不直接从 UI 改背包、金币或贡献。
- 默认共享资金；“累计收益”表示归属于出售者的毛销售额，不是个人钱包或净利润。
- 一次收获、一笔出售、一次捐赠都只能结算一次；物品、资金和统计必须来自同一次业务提交。
- 今日按游戏日，不按用户电脑时区；房主离线不推进世界。
- 私有存档与公开榜单使用不同数据结构；公开默认关闭，玩家行默认不对外发布。
- 自建服务器第一版只要求无界面运行与迁移技术验证，不承诺完整托管平台。
- 无自动接管房主、无全球官方公平榜、无素材侵权、无把不通过的测试写成已通过。

当前状态为“M0 执行中，FND-01 与 UI-01 已分派”。M1–M6 的任务依赖和交付目标已定义，具体签名、命令和数据样例需依照 M0 产物逐阶段填入任务卡，不能把全部后续任务同时当作 READY。12–20 周仅为有明确人员/设备假设的排期参考；未记录证据的时间、性能、玩法时长均不是实测结果。
